# Does `_testinternalcapi` ship where readers get their Python

Generated by `just build-dist`. Do not edit by hand, the change will be overwritten.

12 channels: 8 everything the lessons need, 1 the module, not the functions, 1 no module, 2 not measured.

`_testinternalcapi` is the module that lets a reader run the CPython compiler one stage at a time without building anything. It is private, it has no compatibility guarantee, and the three functions the lessons use (`compiler_codegen`, `optimize_cfg`, `assemble_code_object`) only arrived in 3.12.

## Where a reader hits this

**Fedora python3.** ModuleNotFoundError. Fedora ships a much newer Python than Debian, which makes the answer here a surprise.

**macOS system python3.** module only, missing compiler_codegen, optimize_cfg, assemble_code_object. Not a channel anybody should use, and the one a beginner reaches first, because typing python3 on a Mac finds it. Worth measuring for exactly that reason.

## Not measured, and what would measure it

**python.org installer, macOS.** Installing it needs an administrator password, so this process cannot do it. The payload can be read without installing: fetch the .pkg, run `pkgutil --expand-full` on it, and look for a `_testinternalcapi` shared object under `Python_Framework.pkg`. Somebody who has already installed it can just run the question.

**python.org installer, Windows.** Needs a Windows machine. The installer offers a test suite component, and whether `_testinternalcapi.pyd` lands in a default install is the thing to find out. Run the question printed by `distprobe question` in the installed Python and paste the line into this table.

## Notes on the rest

**uv python install.** The build this project develops against and the one the contributing guide tells people to use. These are the python-build-standalone binaries, which is also what `uvx` and `uv run --python` fetch, so it is a lot of readers. No version in the command because this row is answered by whichever interpreter is running the survey, which is the pinned one, and writing a version there would claim something the run did not check.

**Homebrew.** The usual answer on a Mac that somebody set up for development.

**Debian python3.** Debian stable, so this is what a lot of servers and a lot of WSL installs have.

**Ubuntu python3.** The long term support release, which is what Colab and most tutorials assume.

**Fedora, plus python3-test.** The same image with one more package. On the list because it is the fallback for the row above, and a fallback nobody has run is a guess.

**Official Docker image.** The slim variant, because the full one is a superset and would be an easier question.

**conda-forge.** How a lot of scientific Python arrives, and a completely separate build from the rest.

**Pyodide.** Answered by `wasmprobe` in probes/pyodide, and copied into this table by `distprobe survey` so the two do not have to be read side by side. Issue 1 has the detail.

Containers were run as `linux/arm64`.
